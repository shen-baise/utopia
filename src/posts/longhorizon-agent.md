## 1. 什么是 Long-Horizon Agent

### 1.1 核心定义

**Long-Horizon Agent** 是指能够在**扩展的时间跨度**上自主规划、与环境交互、从错误中恢复并在执行过程中调整策略的智能体系统。

任务需要在推理、工具调用、观察、修正之间反复迭代，跨越许多相互依赖的步骤，短则在单个上下文窗口内完成，长则跨越多个窗口、多次会话，甚至是无边界的任务流。

**长程智能体与长时间运行、自主、自进化**三类智能体。

很多人将 “能跑几小时的智能体” 等同于长程智能体，**Long-running（长时间运行）仅描述执行时长，Long-Horizon（长程）描述任务逻辑耦合度**。一份循环批量处理数据的脚本可以连续运行一周，但每一步相互独立、无依赖，不属于长程任务；而一段在单个上下文窗口内完成完整项目重构的代码工作流，步骤环环相扣、一步错全盘偏，哪怕只运行十分钟，仍是标准长程任务。长程的核心判定标准是**大量相互依赖的决策链条**，而非运行时长。

![818类别对比](../../img/paper/818类别对比.png)

- **vs. Long-Running Execution:** 长时间运行不等于长程智能。真正的 Long-Horizon 要求系统在长期执行中保持**目标一致性**、**错误恢复**和**策略适应**。长运行由"时长"定义，而时长与逻辑耦合是相互独立的两个属性。一个脚本可以跑好几天，但如果它只是对大数据集重复同一操作，各步之间几乎没有依赖，那它既不需要密集的交互式推理，也不需要跨上下文状态管理，就不算长程。
- **vs. Autonomous Agents:** Autonomous 描述自主程度，Long-Horizon 描述时间/步骤跨度。一个 agent 可以短程自主也可以是长程的。自主由"多少步骤无需人类介入"定义，它只是系统的一个治理维度，而非能力度量。一个强大的长程智能体完全可以在层层审批门后以低自主度运行；反之一个高度自主的智能体也许只执行一个单窗口的短任务。
- **vs. Self-Evolving Agents:** 自进化关注能力的跨任务积累（C3），是 Long-Horizon 的子集和高级阶段。自进化由"经验是否持久改变了智能体自身"定义。在本文框架里，自进化只是实现 C3（跨任务经验累积）的一种内化机制，而非长程能力的全部——许多运行在 H1、H2 的智能体用固定策略和临时状态就能完成困难任务，它们没有自进化能力，但依然是长程智能体。

### 1.2 三层能力分级

1. **H1 单上下文任务（分钟级）**

全部流程容纳在单一上下文窗口，对应能力C1：上下文交互式推理，支持循环试错、局部纠错

2. **H2 跨上下文任务（小时至天级）**

任务规模超出单窗口承载上限，需要持久化记忆、任务断点、进度恢复，对应C2跨上下文状态记忆

3. **H3 跨任务开放式流（长期持续）**

无固定终止的连续任务集群，需要沉淀通用技能、从大量历史任务持续迭代优化，对应C3跨任务经验积累，也是自进化Agent专属应用场景

与之对应的三种能力层层累积：

•**C1 — 上下文内交互式推理**（应对 H1）：在单个上下文中，通过与环境和用户的交互持续推理——采取动作、吸收反馈、修正轨迹。

•**C2 — 跨上下文的状态与记忆**（应对 H2）：在 C1 之上，当执行跨越窗口或智能体时维持任务状态——压缩并外化历史、读写记忆、设检查点（checkpoint）、忠实地在交接后恢复。

•**C3 — 跨任务的经验累积**（应对 H3）：在 C2 之上，把经验变成持久能力——在复杂任务间切换、积累可复用技能、从过往经验中泛化，并随目标与环境的漂移持续改进。

| 层级                  | 任务类型                                                     | 核心能力             | 时间跨度 |
| :-------------------- | :----------------------------------------------------------- | :------------------- | :------- |
| **H1: Intra-Context** | 单一上下文窗口内多步耦合任务（plan-act-feedback 循环）       | C1: 交互式推理       | 秒~分钟  |
| **H2: Cross-Context** | 跨多个上下文窗口的任务（需要历史压缩、进度持久化、会话交接） | C2: 状态与记忆管理   | 小时~天  |
| **H3: Cross-Task**    | 持续任务流（环境、工具、目标动态变化，需技能积累与复用）     | C3: 经验积累与自进化 | 天~周+   |

## 2. 为什么这个问题重要且困难

### 2.1 重要性：这是 Agent 落地的核心瓶颈

当前 LLM Agent 系统（如 Claude Code, GPT Codex, Devin）在短程任务上已经展现惊人的能力（SWE-bench Verified 已达 ~70%），但一到需要数小时甚至数天完成的复杂任务时，成功率急剧下降：

- **SWE-Bench Pro**（多文件、多步骤的真实软件工程任务）：最强模型 GPT-5 仅 **23.3%**
- **SWE-Marathon**（超长程软件任务，平均 2720万 token/trial）：没有任何配置超过 **30% pass@1**
- **Long-Horizon-Terminal-Bench**（46个终端任务）：SOTA 仅 **15.2%**（部分奖励）、**10.9%**（完美奖励）

### 2.2 长程任务三大瓶颈

综述归纳了长程智能体落地时反复出现的共性痛点：

1. **目标漂移与误差累积**：在成千上万步的执行中，智能体会慢慢偏离最初的目标；由于没有任何一步是完美可靠的，局部误差沿轨迹累积，最终把整个推理引向错误路径。
2. **上下文腐化**：随着工作上下文被填满，智能体在越过某个"上下文利用率阈值"后性能会骤然下降；反过来，一个感知到自己接近上下文极限的智能体，又可能过早终止，把"部分完成"当成"成功"上报。
3. **稀疏延迟奖励+不可逆操作**：许多长程任务只在最终才给出奖励，中间决策几乎没有学习信号；而且智能体行动越久，越可能执行有风险、不可逆的操作，因此监控执行安全与可恢复性变得至关重要。

单纯扩大上下文、提升模型推理力只是治标，**必须联合外部调度框架+内部模型双向协同优化**。

| 困难维度                            | 具体表现                                                     |
| :---------------------------------- | :----------------------------------------------------------- |
| **1. 目标漂移 (Goal Drift)**        | 随着步骤增加，agent 逐渐偏离原始目标，尤其是在遇到困难时选择"捷径" |
| **2. 错误累积 (Error Compounding)** | 每一步的小错误在成百上千步中指数级放大，导致不可逆失败       |
| **3. 上下文退化 (Context Rot)**     | 中间输出不断堆在 context window 中，信息密度下降，推理质量退化 |
| **4. 信用分配 (Credit Assignment)** | 稀疏的最终结果奖励无法区分哪个中间步骤真正贡献了成功/失败    |
| **5. 记忆漂移 (Memory Drift)**      | 自维护的记忆经过多次总结/压缩后，关键信息变形或丢失          |
| **6. 不可逆操作风险**               | 错误操作（删除数据、错误授权、覆盖文件）在长程任务中风险远高于短程 |

## 3. 领域发展三阶段

#### 阶段1：Prompt Engineering（2020–2023）

控制单元仅单轮提示，依靠CoT、少样本挖掘模型原生推理。仅具备基础C1单上下文能力，无持久记忆、循环调度，属于Agent雏形，无法跨窗口执行任务。

#### 阶段2：Context Engineering（2023–2025）

控制范围拓展至模型输入层，RAG检索、工具调用、百万级长上下文、短时记忆成熟，同时拥有C1、部分C2能力，但无完整持续运行时，任务中断后无法自动续跑，仅能分段完成长流程。

#### 阶段3：Runtime Harness（2025至今）

运行时调度框架成为标配，循环、持久记忆、多层校验、多智能体编排标准化，C1/C2能力完全成熟，部分系统实现C3跨任务自进化，也是当前企业主流技术路线。

## 4.双支柱核心架构：外部调度层 + 内部模型优化

一套完整长程智能体由两大协同进化模块共同构成，分别是外部调度框架（Harness）和内置模型策略。二者属于协同进化关系，早期依靠Harness搭建基础长流程能力，再通过训练把调度逻辑内化进模型；模型变强后，又能支撑轻量化、更复杂调度架构迭代，形成正向循环

### 支柱一：外部调度框架Harness六大核心组件

![818harness](../../img/paper/818harness.png)

**1. 循环与工作流**

循环决定任务如何推进。简单任务可以沿一条路径连续执行；复杂任务需要先规划再执行；不确定性较高的任务则可能同时探索多条路径，通过比较、剪枝或回退选择更可靠的方案。

**2. 上下文与记忆**

工作上下文保存当前步骤需要的信息，持久记忆保存跨窗口和跨任务仍有价值的状态。关键不是记录一切，而是及时总结、压缩和刷新，避免日志与工具输出淹没核心目标。

**3. 工具、MCP与技能**

工具让模型能够搜索网页、运行代码、读写文件和操作外部系统；MCP等协议试图统一工具发现、连接和授权方式；技能库则将成熟流程封装为可重复调用的操作单元，减少每次从头规划带来的不稳定性。

**4. 编排系统**

当一条循环无法处理所有工作时，编排层负责拆分任务、分配角色、选择模型，并协调多个智能体。多智能体并不天然优于单智能体，额外通信可能制造信息损失和协调成本，因此只有可以明确分工或并行验证的任务才真正受益。组织超出单个智能体循环的工作，包括任务分解、角色分配、路由与智能体间协调，以及编排优化和 A2A 等智能体协议。

**5. Hooks与中间件**

在运行时提供预定义的拦截点，让执行可以被检查、修改、暂停或交接。分为预定义规则钩子、用户自定义钩子和运行时自适应钩子。

**6. 验证机制**

验证对象不仅是最终答案，也包括中间状态、工具参数和外部副作用。代码任务可以依靠编译器与测试，信息检索需要证据与引用检查，电脑操作则要确认界面状态是否真的发生预期变化。

### 支柱二：内部模型优化七大训练链路

Harness能够在模型外部补充规划、记忆、工具调用和验证能力，但如果所有行为都依赖复杂的外部流程，系统会变得昂贵且脆弱，因此需要把Harness中已经验证有效的能力，逐步**内化到模型参数中**。

![818model](../../img/paper/818model.png)

**1. 架构基础**

模型首先要能够表示并高效处理长轨迹，包括历史对话、工具结果、环境状态和任务约束。显式长上下文、压缩状态、混合记忆及高吞吐机制，分别在信息完整性与计算成本之间寻找平衡。

**2. 数据与环境合成**

长程训练不能只依靠静态问答数据，还需要生成可执行、可验证的任务、环境和交互轨迹。代码仓库、网页、工具沙箱和模拟桌面等环境，可以让模型通过实际行动获得反馈。

**3. 预训练与中期训练**

这一阶段为模型建立多步推理、长上下文理解、工具使用和多模态感知等基础能力。它的作用不是教会模型某个固定工作流，而是为后续智能体训练提供更合适的能力底座。

**4. 微调**

微调利用筛选后的智能体轨迹，让模型掌握稳定的行动规范，例如如何调用工具、如何根据反馈调整方案，以及如何在执行过程中保持目标一致。其局限是主要模仿已有轨迹，探索新策略的能力有限。

**5. 智能体强化学习**

强化学习根据测试结果、环境状态或任务完成情况优化整条执行轨迹。最大的困难是**奖励稀疏与信用分配，任务最后失败时，系统很难确定究竟是哪一个中间决策造成了问题。**

![818强化学习](../../img/paper/818强化学习.png)

> **智能体强化学习的四个关键问题——信用分配、策略优化、采样策略、交互结构。]**

•**信用分配**：结果信用（终端奖励）、过程信用（中间信号）、准则信用（显式评分标准）等多粒度信号；

•**策略优化**：基于裁剪的优化、轮次级优化、基于熵的优化（保持探索）；

•**采样策略**：轨迹 rollout、树采样（共享计算）、预算控制；

•**交互结构**：分层框架（时序抽象）、多智能体联合决策、可学习的记忆管理。

**6. 同策略蒸馏**

同策略蒸馏让模型从自身当前策略产生的轨迹中学习，再由教师模型或验证器提供指导。它可以覆盖模型实际运行时会遇到的错误状态，减少训练数据与真实部署之间的偏差。

**7. 自进化**

自进化进一步把部署经验转化为持续改进，包括积累新轨迹、生成更难任务、更新技能与工作流，甚至继续优化模型参数。但自生成数据可能固化错误，弱验证器也可能引发奖励投机，因此仍需要独立验证和离线审计。把智能体自己产生的经验、反馈与任务—环境更新，转化为持续的策略改进。分为离线自进化、在线自进化，以及**智能体—环境协同演化**——后者把训练环境本身也当作可更新的对象：环境太易只会强化已有策略，太难则给不出可用信号。

这七个环节构成了一条完整链路：架构负责承载长轨迹，数据和环境提供经验，预训练与微调建立行为基础，强化学习和在策略蒸馏优化真实决策，自进化则让能力跨任务积累。它们与Harness并非相互替代，而是把外部脚手架中成熟的能力逐步吸收到模型内部。

## 5.前沿开放挑战

### 进化维度：自进化与跨框架迁移

未来的Harness可能自动修改工作流、生成技能并适应新模型，但流程自修改也可能放大错误。如何把经验转化为稳定能力，同时保持可审计性，是持续学习的核心问题。支架能否自我进化？习得的能力能否跨支架迁移？经验能否跨回合复利以致终身学习而不破坏已有能力？

### 有效性维度：真实世界可靠交互

下一阶段的限制因素可能不是模型规模，而是训练环境。真实环境昂贵、缓慢且存在不可逆操作；模拟环境容易验证，却可能与现实存在差距。如何兼顾真实性与可验证性，将直接影响训练效果。在真实、含噪、有代价的环境中行动。真实环境可能返回被操纵或对抗性的观察；同时要从数字世界迈向具身智能体。

### 效率维度：算力、上下文、模态成本管控

当前智能体普遍缺乏成本意识，容易在每一步调用最强模型、重复读取上下文，并在已经失败的路径上继续消耗资源。未来系统需要预测任务难度，在模型、上下文、工具调用、时间和验证强度之间动态分配预算。

### 可信维度：长周期安全与鲁棒性

长程智能体运行越久，接触的数据和工具越多，错误影响范围也越大。外部信息可能包含恶意指令，记忆与技能库可能积累危险经验，自修改流程还可能破坏原有安全规则。

两个方向不是对立的，而是形成**双向增强循环**：
